# Getting Support

Use the right channel so maintainers and the community can help quickly:

## Questions, setup, and architecture

Start a thread in **[GitHub Discussions](https://github.com/auditstream/auditstream/discussions)** or check the documentation at **[auditstream.dev/docs](https://auditstream.dev/docs/)**:

- PostgreSQL setup, pooler configuration (PgBouncer, Neon, Supabase Supavisor, RDS Proxy), and migration workflows
- Prisma, Drizzle, Next.js, Hono, Express, or plain SQL integration questions
- Ideas, RFC feedback, and roadmap discussions

## Bugs and feature requests

Open an issue using the structured templates on **[GitHub Issues](https://github.com/auditstream/auditstream/issues/new/choose)**:

- **Bug report** — unexpected CLI, generated SQL, or capture behavior with a minimal reproducer
- **Feature request** — new CLI, engine, or operational capabilities
- **Spec change** — proposals affecting `spec/` wire format or conformance fixtures

## Security vulnerabilities

**Do not open a public issue or discussion for security reports.**

Submit security reports privately through **[GitHub Private Vulnerability Reporting](https://github.com/auditstream/auditstream/security/advisories/new)** or email **security@auditstream.dev**. See [SECURITY.md](SECURITY.md) for response targets, supported versions, and requirements for AI-assisted reports.

## Code of conduct

All community spaces follow our [Code of Conduct](CODE_OF_CONDUCT.md). Contact **conduct@auditstream.dev** for moderation or conduct issues.
