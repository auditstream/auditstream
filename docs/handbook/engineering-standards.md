# Engineering standards

Each repository has one command that runs every quality gate locally, the same gates run in CI, and nothing merges with a red check.

## Toolchains and quality gates

| Gate | Engine (Rust) | auditstream-js (TypeScript) |
| --- | --- | --- |
| Local entry point | `cargo xtask ci` | `pnpm check` |
| Toolchain | Rust 1.100 pinned in `rust-toolchain.toml`, edition 2024, MSRV 1.96 checked with `cargo hack` (sqlx 0.9 needs 1.94) | Node 26 for development; packages support 22.12 or newer. pnpm 12 with catalogs. TypeScript 6.0, because API Extractor still needs the compiler API that TypeScript 7.0 does not ship until 7.1; a non-blocking TypeScript 7 check runs alongside |
| Format | `cargo fmt --check` | Biome 2.6 |
| Lint | clippy `-D warnings`: pedantic with an allowlist, plus `unwrap_used`, `dbg_macro`, `todo`, `await_holding_lock`; `unsafe_code = forbid` | Biome; strict tsconfig with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `isolatedDeclarations`. Biome's floating-promise rule is still in its nursery group, so promise handling is also covered by review |
| Unit and property tests | cargo-nextest, proptest; `cargo test --doc` separately, since nextest skips doctests | Vitest 5 |
| Snapshots | insta for generated SQL and CLI output | Vitest snapshots |
| Postgres tests | One harness: `DATABASE_URL` if set, testcontainers otherwise; one database per test; CI matrix PostgreSQL 15 to 19 | Same rule with `TEST_DATABASE_URL` and `@testcontainers/postgresql` |
| Version matrix | PostgreSQL 15 to 19 | Node 22, 24, 26; Prisma 7.x; Drizzle 0.45 and 1.x; weekly job on `latest` and `rc` tags |
| Concurrency tests | Not applicable | Every adapter runs at least 40 concurrent requests with distinct actors through a pool smaller than the request count and expects zero wrong actors |
| Dependencies and licenses | cargo-deny: licenses, advisories, bans and sources | pnpm `minimumReleaseAge` of 1 day |
| Public API | rustdoc with `-D warnings` | API Extractor report committed; publint and arethetypeswrong on the packed tarball |
| Coverage | cargo-llvm-cov, reported, not blocking | Vitest coverage, reported, not blocking |
| Build | cargo | tsdown 0.23, pinned exactly, ESM only |
| Task runner | xtask | Turborepo 2.11, running only what a pull request affects |

## Testing strategy

- **Unit tests** cover pure logic: codec, diff, redaction, CSV escaping. Property tests cover round-trips.
- **Snapshot tests** pin the SQL generated for each fixture schema, once per output format (Prisma, Drizzle, plain SQL).
- **Integration tests** run every capture scenario against real Postgres: nested writes, bulk updates, cascades, no-op updates, excluded columns, TRUNCATE, tables without a primary key.
- **Conformance tests** run the shared fixtures from `spec/conformance/` in both repositories.
- **End-to-end tests** drive the CLI binary with assert\_cmd and insta-cmd, and drive each adapter against a migration generated by the real engine.
- **Benchmarks** run nightly with pgbench and publish the cost per write.

## CI workflows

| Workflow | Runs |
| --- | --- |
| `ci.yml` | Format first, then lint, tests, docs, MSRV and dependency checks in parallel, on every pull request |
| `pr-title.yml` | Conventional Commits check on the pull request title |
| `labels.yml` | Syncs labels from `.github/labels.yml` |
| `audit.yml` | Daily advisory scan |
| `nightly.yml` | Benchmarks and the ORM `latest` and `rc` matrix |
| `release-plz.yml`, `release.yml` (engine) | Release pull request, tag, binaries |
| `release.yml` (auditstream-js) | Changesets release pull request and npm publish |

Caching uses `Swatinem/rust-cache` and saves only on `main`. Tools install with `taiki-e/install-action`. Lints live in `[workspace.lints]`, not in RUSTFLAGS, so they do not break the cache.
